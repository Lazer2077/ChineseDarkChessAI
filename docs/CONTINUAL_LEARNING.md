# Continual value-based expert iteration

The earlier experiments trained on a fixed teacher dataset. This controller
adds the missing actor/learner/replay/gate cycle. It remains a value-based
NNUE + alpha-beta method on the attributed MIT jqe architecture, not AlphaZero,
PPO or a full POMCP/CFR implementation.

1. The current best network guides observer-specific native selfplay searches.
   Reveals and private dark captures follow each actor's own observation.
2. Valid completed games produce search scores and terminal outcome labels.
   Resource-truncated/error games contribute no training records; rejected
   counts are explicitly logged. Search itself is unchanged from the backbone.
3. The learner warm-starts from the current best network and trains on a sliding
   replay window, mixing 70% search-value and 30% outcome targets in expected-
   score space. Data and minibatch computations run on the selected GPU.
4. A fixed-clock paired gate compares the candidate with the previous actor.
   The next generation uses the new actor only when its internal gate passes.
   Rejected candidates remain recorded; an internal gate is not an overall
   all-engine superiority claim. Baseline-opponent coverage remains separate.

## First expanded series, frozen before launch
- Three independent training seeds: 20261026, 20261027, 20261028.
- Two iterations per seed; 8,192 games per iteration, 5,000 nodes/move,
  four CPU actor workers. Total planned: 49,152 training games.
- 512 validation games per seed, generated by the original fixed teacher with
  disjoint generation seeds. Validation is fixed within each independent run.
- Replay window: latest two completed generations. GPU batch 4,096, 15 epochs,
  learning rate 2e-5, lambda 0.7, score scale 430. No multi-GPU/DDP claim.
- GPU 2 only; seeds run sequentially. CPU search is expected to dominate runtime.
- Gate: 200 games / 100 layout pairs; 5 seconds + 0.05 seconds/move actual clock,
  one engine thread, 64 MB hash, two concurrent games. Preload and clear each
  engine before its clock starts. Technical failures prevent acceptance.
- Internal acceptance requires both paired bootstrap and bounded Hoeffding
  95% lower limits above 0.5. Goal-level independent confirmation is separate.

This is materially larger than the 512-game pilot, but the number of games,
retained positions, optimizer steps and actual GPU use must be read from live
records before calling it a completed large-scale RL run. NNUE is a small model;
occupying several GPUs would not by itself improve the experiment.

## Recovery and provenance
The controller holds an OS file lock, checkpoints JSON state atomically, pins
actor/teacher/trainer/controller hashes, and records each active subprocess PID.
It never treats a missing console update as job completion. On recovery it
refuses to start while a recorded matching child is live, verifies completed
artifact hashes and recipes, and preserves incomplete generation/model folders
as aborted artifacts before retrying a terminal stage. Data files are finalized
only after the native completion count and file size agree.

The two-iteration functional smoke generated 2,002 retained positions and
exercised both replay sizes 1 and 2. Very short 0.5+0.005 smoke clocks produced
technical forfeits; the controller correctly rejected both candidates. These
are orchestration tests, not strength evidence. An identical restart skipped
all completed generation, learning and gate work without duplicating history.
A separate maxply=1 test rejected all three games and wrote zero training bytes.

## Run
Build the pinned native backbone and independent referee first (ADAPTIVE_SEARCH.md),
then build the data actor with `python3 scripts/build_data_actor.py`.
Use the PyTorch interpreter for the controller, and Python 3.11+ for its referee.

```sh
CUDA_VISIBLE_DEVICES=2 OMP_NUM_THREADS=2 python scripts/continual_learning.py \
  --out=runs/your-new-run --seed=20261026 --iterations=2 --games=8192 \
  --nodes=5000 --workers=4 --epochs=15 --batch=4096 \
  --referee-python=/absolute/path/to/python3.11
```

Rerun with the identical command to recover. Use a new directory for changed
configurations. Keep a background launcher's script immutable while it runs.
